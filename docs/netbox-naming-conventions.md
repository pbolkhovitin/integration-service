# Нейминг NetBox — единый источник истины по сетевой инфраструктуре и мониторингу

> Версия 0.1 (для утверждения с руководством).
> Назначение: единые правила именования объектов NetBox, чтобы CMDB оставалась
> читаемой, масштабируемой и однозначно связывалась с Zabbix и GLPI.

## Роли систем

| Система | Роль | Содержимое |
|---|---|---|
| **NetBox** | Единый источник истины (SoT) по сетевой инфраструктуре и мониторингу | Все мониторимые устройства: серверы, сетевое оборудование, СХД, Wi-Fi, ИБП/PDU |
| **Zabbix** | Мониторинг | Хосты для мониторинга — **только из NetBox** (netbox-zabbix-sync) |
| **GLPI** | ITAM + Service Desk | Пользовательские ПК, мониторы, принтеры, сканеры + заявки на ремонт/обслуживание; активы импортируются из NetBox (read-only) |

## Принципы

1. NetBox содержит **только мониторимые/сетевые** устройства (серверы, коммутаторы, маршрутизаторы, СХД, Wi-Fi-ТД, ИБП/PDU).
2. Пользовательские ПК/ноутбуки/принтеры — **в GLPI** (ITAM), НЕ в NetBox (кроме случаев, когда ПК мониторится — тогда в NetBox с ролью `pc`, см. ниже).
3. Нейминг — **латиницей**, ASCII, короткие коды. Кириллица недопустима (Zabbix/скрипты).
4. Каждое устройство имеет уникальное имя = `ROLE-SITE-NNN`.
5. Любые изменения — через NetBox (он источник), на Zabbix/GLPI переносятся интеграцией.

## Sites (площадки)

| Поле | Правило | Пример |
|---|---|---|
| name | `CODE-Site` (короткий код площадки) | `COD-Behteeva`, `Cod-RTP`, `Opytnaya`, `Signal-Ofice` |
| slug | lowercase, дефисы | `cod-behteeva` |
| description | назначение/адрес | `Головной офис, ул. ...` |

## Locations (локации: стойки/комнаты)

- Формат: `SITE-<комната/стойка>-<номер>` или `SITE-<номер стойки>`
- Пример: `Opytnaya-1` (серверная №1), `Signal-Ofice-rack-2`

## Device types (модели)

- Формат: `Manufacturer Model` (как у вендора)
- Пример: `MikroTik RB3011UiAS-RM`, `Super Micro X11DPi-N`, `Ubiquiti US8P150`

## Device roles

| Роль (name) | Код в имени | Назначение |
|---|---|---|
| `server` | `SRV` | Серверы (физические) |
| `storage` | `STO` | СХД/хранилища |
| `switch-core` | `SWC` | Ядро сети |
| `switch-dist` | `SWD` | Распределение |
| `switch-access` | `SWA` | Доступ |
| `router` | `RT` | Маршрутизаторы |
| `firewall` | `FW` | Межсетевые экраны |
| `wifi-ap` | `AP` | Точки доступа Wi-Fi |
| `ups` | `UPS` | ИБП |
| `pdu` | `PDU` | Блоки распределения питания |
| `pc` (только мониторимые АРМ) | `PC` | Пользовательские ПК под мониторингом |

## Имена устройств (device name)

- Формат: `ROLE-CODE-SEQ` (SEQ — 2-3 цифры, 01..)
- Примеры:
  - `SRV-KG-01` — сервер №1 площадки KG
  - `SWA-KG-25` — коммутатор доступа №25 площадки KG
  - `AP-KG-07` — точка доступа №7
  - `FW-01` — файрвол №1 (если площадка одна — префикс можно опускать)
- **Серийный номер, MAC** — обязательны (для связи с GLPI и Zabbix).
- **Статус**: `Active` / `Planned` / `Offline` / `Decommissioning` / `Inventory` / `Staged` / `Failed` — влияет на хост в Zabbix (Active → включён, Offline/Planned → выключен, Decommissioning → удалён).

## Теги (tags)

- `environment: prod|test|dev` (NetBox tag: `prod`, `test`, `dev`)
- `site:<code>` (генерируется)
- Произвольные операционные: `critical`, `backup` и т.п.

## Кастомные поля (для интеграций)

| Поле | Тип | Объект | Назначение |
|---|---|---|---|
| `zabbix_hostid` | Integer | device | ID хоста в Zabbix (заполняет netbox-zabbix-sync) |
| `zabbix_template` | Text | device_type | Шаблон Zabbix по умолчанию |
| `owner` | Text | device | ФИО владельца (для ПК под мониторингом) |
| `department` | Text | device | Отдел/подразделение |

## Что НЕ вносим в NetBox

- Пользовательские ПК/ноутбуки (кроме мониторимых) → **GLPI**
- Мониторы, принтеры, сканеры → **GLPI**
- Расходные материалы, кабели (если не нужны для мониторинга) → **GLPI** / docs-signal-infa

## Правила создания

1. Сначала заводится Site → Location → Device type → Device.
2. Устройство создаётся в NetBox → netbox-zabbix-sync создаёт хост в Zabbix → устройство импортируется в GLPI.
3. Удаление/декомиссия — только через NetBox (статус `Decommissioning`), интеграции синхронизируют.

## Планируемые поля/объекты — на доработку

- VRF/IP-plan, IPAM-политика (по мере внедрения)
- Virtual machines (кластеры) — отдельная политика
